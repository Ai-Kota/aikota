## 2. 测试策略

### 2.1 测试分层

```
┌─────────────────────────────────────────────────────────┐
│                    E2E 测试（集成）                       │
│  位置：internal/cli/*/ 与 integration/                   │
│  目标：验证完整用户流程（启动→运行→退出）                  │
│  频率：每次 PR 手动运行                                 │
├─────────────────────────────────────────────────────────┤
│                    单元测试（模块）                       │
│  位置：internal/<pkg>/*_test.go                        │
│  目标：验证单个函数/方法的行为                           │
│  频率：每次提交自动运行                                 │
├─────────────────────────────────────────────────────────┤
│                    表驱动测试                            │
│  位置：所有 *_test.go                                   │
│  目标：覆盖边界条件与错误路径                            │
│  频率：每次提交自动运行                                 │
├─────────────────────────────────────────────────────────┤
│                    Golden Test                           │
│  位置：*_test.go 中的 golden 文件                       │
│  目标：验证输出格式稳定性                               │
│  频率：每次提交自动运行                                 │
└─────────────────────────────────────────────────────────┘
```

### 2.2 测试命名约定

```go
// 成功路径
func TestXxx_SuccessCase(t *testing.T) {}

// 失败路径
func TestXxx_ErrorCase(t *testing.T) {}

// 边界条件
func TestXxx_EdgeCase(t *testing.T) {}

// 并发安全
func TestXxx_ConcurrentAccess(t *testing.T) {}

// 超时/取消
func TestXxx_ContextCancellation(t *testing.T) {}

// Golden 输出
func TestXxx_OutputMatchesGolden(t *testing.T) {}
```

### 2.3 Mock 策略

| 依赖类型 | Mock 方式 | 示例 |
|----------|-----------|------|
| `provider.Provider` | 接口 + 实现 `fakeProvider` | `internal/provider/responses.go:49` |
| `fs.FS` / 文件系统 | `os.CreateTemp` + `t.Cleanup` | `internal/dream/*_test.go` |
| HTTP transport | `httptest.Server` | `internal/provider/*_test.go` |
| 子进程 | `fakeSubprocess` 接口 | `internal/dream/runner_test.go` |
| 时间 | `fakeTime` + `time.Now` 注入 | `internal/dream/state_test.go` |

## 5. CI 测试矩阵

### 5.1 当前 CI 配置

```yaml
# .github/workflows/ci.yml
jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - run: go test ./... -count=1
      - run: go test ./... -race -count=1
      - run: go vet ./...
```

### 5.2 新增 CI 检查项

| 检查项 | 命令 | 频率 |
|--------|------|------|
| 单元测试 | `go test ./... -count=1` | 每次 PR |
| Race Detector | `go test ./... -race -count=1` | 每次 PR |
| 覆盖率检查 | `go test ./... -coverprofile=coverage.out` | 每次 PR |
| Golden Test | `go test ./... -run TestGolden` | 每次 PR |
| E2E 测试 | `go test ./internal/cli/... -run TestE2E` | 每周/手动 |

### 5.3 覆盖率门禁

```bash
# 要求整体覆盖率不低于 85%
go test ./... -coverprofile=coverage.out
go tool cover -func=coverage.out | grep "^total:" | awk '{if ($3+0 < 85) exit 1}'
```

func TestStatus_Output(t *testing.T) {
    cases := []struct {
        name     string
        host     cli.Host
        expected string
    }{
        {
            name: "basic",
            host: newFakeHostBasic(),
            expected: "testdata/status_basic.golden",
        },
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            var buf bytes.Buffer
            status.RunStatus(&buf, tc.host)
            if got, want := buf.String(), readGolden(tc.expected); got != want {
                t.Errorf("got\n%s\nwant\n%s", got, want)
            }
        })
    }
}

## 7. 已知测试问题

### 7.1 Windows 8.3 短名问题

**现象**：`TestCwdChdirRootsEnv` 在 Windows CI 失败

**原因**：临时目录短名 vs 长名不一致

**状态**：已记录，待修复

**临时方案**：在测试中使用 `os.MkdirTemp` 并确保路径规范化

---

### 7.2 Dream 测试中的 LLM 依赖

**现象**：`TestDream_*` 需要 LLM 但测试环境无网络

**解决方案**：
- 使用 `fakeLLMConsolidator` 替代真实 LLM
- 验证确定性逻辑（dedup、path clean）不需要 LLM
- 仅 E2E 测试需要真实 LLM

---

### 7.3 并发测试稳定性

**现象**：某些并发测试在 CI 上偶尔失败

**解决方案**：
- 增加重试逻辑（`t Retry(3, ...)`）
- 使用 `testify/suite` 管理测试生命周期
- 避免依赖时间精确性
